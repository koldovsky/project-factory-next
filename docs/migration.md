# Migrate from the previous project factory

Keep the old repository available for reference. Start a new control bundle for each product/task family and move only reviewed requirements and useful lessons.

| Previous mechanism | Replacement |
|---|---|
| Markdown verification keywords | Explicit requirement → check → exact case mappings |
| Workspace integrity lock and `Refs: PD-*` approval | Complete sealed control bundle plus separately selected policy digest |
| Generic report file existence | Strict affirmative case outcomes and current-run artifact hashes |
| Filesystem freshness windows | Candidate, policy, evaluator and evidence content identity |
| Ratchets that rewrite tolerated lower scores | Fixed preregistered quality floors and externally controlled policy updates |
| Lifetime vacuous-pass count blocking forever | Immutable history with current-run acceptance and evidence-linked failure intake |
| QA consumers before evidence producers | Dependency-ordered checks with explicit blocked outcomes |
| Prose-only promotion criteria | Executable paired experiment assessor and external promotion decision |
| Copied provider-specific process instructions | Portable core plus versioned task profile and native runtime adapter |
| CI template without active enforcement | Real source CI and explicit product-evaluator deployment contract |

For each migrated rule, write a valid example and an unseen failure it should catch. Also test cases where the rule should not apply. Preserve source links, scope, installed version and retirement conditions for lessons. A long prompt is not inherently a better factory.

Run one narrow task family in parallel with the existing process. Compare acceptance, escaped defects, human effort, elapsed time and cost. Move more work only when the new system establishes useful outcomes, not merely more generated code.
